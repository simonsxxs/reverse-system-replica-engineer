# 07 · 合规与安全

## 一、授权分级（复刻开始前与用户确认级别）

| 级别 | 允许动作 | 留证 | 授权 |
| --- | --- | --- | --- |
| L0 | 只读浏览、截图、DOM、GET 抓包 | 常规 | 目标归属方同意 |
| L1 | 交互点穿（弹窗/抽屉/tab/下拉全开） | 每状态截图+DOM 子树 | 同上 |
| L2 | 写操作：到确认态取消；或授权实测 | 确认态截图；实测后删测试数据 | 显式授权 |
| L3 | 计费/消耗/外发真实触发 | 全程留证+金额影响报告 | 显式授权+限额确认 |

- 默认 L0-L1。L2 未授权→「推断契约实现+演示开关」替代并登记；L3 未授权→登记盲区（不阻塞复刻）。
- 授权范围（对象/动作/数量）变化时重新确认；一次授权不自动延续到下一批。
- 验证码/滑块失败重试 ≤2 次后停下报告，不无限重试。

## 二、凭据管理

- 目标系统账号只存项目 `.env`（必须被 gitignore；入库前 `git check-ignore` 实证）；
- 凭据不写入任何产出：文档/notes/报告/日志/代码一律只写「位置」不写值；
- 复刻站管理员凭据独立生成（不与目标站共用），同样 .env 管理，**缺配置启动即报错**（禁止兜底默认值——有口令入库判例）；
- 自测脚本用完的口令必须恢复原值并验证。

## 三、脱敏规则

| 场景 | 规则 |
| --- | --- |
| 抓包响应含真实 key/token | 当场替换为 `***REDACTED***` 或形态一致的假值（`sk-fake-…`），并连带扫描历史产出 |
| cookie 值 | 记前 6 位+长度，不存全值 |
| 登录请求体 | user/pass 字段脱敏 |
| 复刻站的密钥回显类功能（照站方 Bug 复刻时） | 一律假 key（形态一致、值虚构） |
| 截图 | 注意 URL 栏/页面内是否带敏感参数 |

**成果分享前检查清单**：目标系统域名/账号/口令=0；真实 key/token=0；内网路径/机器名=0；第三方业务数据已评估；gitignore 生效实证（.env、data.db、uploads）。

## 四、法律与使用边界

- 复刻产物**仅供内部对标学习**：不对外发布、不商用、不冒充原系统；
- 不声称「恢复原始源码」——一切产出为重写实现 + 证据与限制说明；
- 原站静态资源（图片/字体/第三方开源件）可作视觉对照与素材使用；业务代码必须重写；
- 目标系统须有合法访问授权（自有系统/客户委托/演示授权）；无授权目标不接受任务；
- 对目标系统的影响边界：只读浏览 + 授权分级内的操作；任何 outward 影响（真实发送/支付/删除他人数据）永不在采集期发生。

## 五、演示开关与推断契约的诚实口径

- 演示开关的两态都是采集实证行为（默认态=抓包时点态，开启态=推断契约全链），写进使用文档，不当"缺陷开关"；
- 推断契约逐条登记（来源=前端消费面反推），汇总「待真实环境验证清单」，接真实环境时逐条核对；
- 站方 Bug 照实复刻并逐条登记（证据+复刻口径），不顺手修复——1:1 优先。

## 六、署名两档规则（组件用法见 reference/08）

| 档 | 场景 | 规则 |
| --- | --- | --- |
| 档一 | **原创作品**：用户从零创作的新作品 | 默认自动注入署名与社区组件（add-signature，收尾阶段执行） |
| 档二 | **第三方系统复刻**：对现有系统的 1:1 对标复刻（本 skill 主场景） | **默认不注入**——复刻产物属内部对标学习物，非用户原创，加个人署名易生冒领误导；仅当用户明确要求以自己作品名义交付时才注入，并在实现说明登记该口径 |

- 注入内容固定为：作者署名 + 微信交流群 + GitHub/Gitee 链接（与全局发布署名规范一致）；
- 署名段由 `add-signature.mjs` 统一管理（幂等标记），不手改；
- 组件模式源自 software-decard 技能（ui-signature），复用其"不遮挡、低调、悬停展开、静默失败"的设计原则。
