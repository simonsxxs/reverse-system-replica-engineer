# 08 · 署名与社区组件（v2.4 · 风格自适应）

> 组件模式源自 software-decard 技能的 `references/ui-signature.user.js`（右下角胶囊 + 悬停弹层 + QR data URI 内嵌 + 静默失败），本 skill 将其改造为「注入式」交付组件。

## 一、是什么

| 组成 | 内容 |
| --- | --- |
| `assets/signature.json` | 署名数据源：author / wechat / github / gitee / pillText / overrides（令牌覆写） |
| `assets/wechat-qr.b64` | 微信群二维码 PNG base64（内嵌进组件，运行时以 data URI 展示） |
| `scripts/add-signature.mjs` | 注入工具：`node add-signature.mjs <项目目录> [--selftest]` |

注入后项目获得：

1. **README.md** 末尾追加标准署名段（含 `signature-block:v2.4` 标记，幂等：已含标记跳过；无 README 则新建）；
2. **全部 .html** 在 `</body>` 前注入 `signature.css` + `signature.js` 引用（相对路径，子目录页面自动回退 `../static/`；幂等）；
3. **`static/signature.js|css`**：右下角胶囊「加入社区」，悬停/点击展开弹层——微信二维码 + 群号（点击复制）+ 作者 + GitHub/Gitee 链接；任何异常静默失败，绝不挡内容。

## 二、风格自适应机制（组件的核心）

组件渲染时不硬编码配色，运行时按以下优先级探测宿主风格，逐级降级：

| 令牌 | 探测优先级（先命中先用） | 全部落空时的默认 |
| --- | --- | --- |
| 强调色（胶囊圆点/链接色） | `overrides.accent` → 宿主 CSS 变量 `--accent`/`--primary`/`--primary-color` → **既有按钮的实色背景**（跳过透明与近灰白/近黑的"中性色"） | 浅色 `#07c160` / 深色 `#4f8cff` |
| 文本色 | `overrides.text` → `--text`/`--foreground` → body 计算色 | 按深浅色给中性值 |
| 底色与明暗 | `overrides.bg`/`overrides.dark` → `--bg`/`--background` → body 背景色做**亮度判定** | 中性毛玻璃（浅色白玻璃 / 深色烟黑玻璃） |
| 圆角/字体 | 既有按钮的 `border-radius`（过大收敛为 12px）/ body `font-family` | 999px 胶囊 + 系统栈 |

- 圆点/链接用宿主强调色点缀，胶囊与弹层底保持中性毛玻璃——**既融入宿主又不打架**；
- `assets/signature.json` 的 `overrides` 可压过一切探测（如 `{"accent": "#07c160", "dark": true}`）；
- "渲染色与宿主令牌一致"由 `scripts/validate.mjs` 实测断言（胶囊强调色 === 宿主按钮色），不是声明。

## 三、合规两档（注入前必判，细则见 07 §六）

| 档 | 场景 | 默认动作 |
| --- | --- | --- |
| 档一 · 原创作品 | 用户从零创作的新作品（scaffold 起的自己的项目） | **自动注入署名**（收尾阶段执行，GOAL 登记口径） |
| 档二 · 第三方系统复刻 | 本 skill 的主场景：对现有系统的 1:1 对标复刻 | **默认不注入**——复刻产物属对标学习物，加个人署名易生"冒领"误导；仅当用户明确要求以自己作品名义交付时才注入，并在实现说明登记 |

## 四、用法

```bash
# 注入（目标=frontend 交付目录；不要指向含逆向采集证据的项目根）
node <skill目录>/scripts/add-signature.mjs <frontend目录>

# 自检（对内置靶场副本注入两遍：注入点存在 + 幂等 + 内容零变化）
node <skill目录>/scripts/add-signature.mjs <任意目录> --selftest
```

幂等性：重复运行安全——已注入的 HTML/README 跳过，组件文件内容一致则不动。改 `signature.json` 后重跑即更新组件文件。
