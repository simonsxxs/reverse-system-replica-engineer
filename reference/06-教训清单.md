# 06 · 教训清单（每条=现象→根因→对策）

> 全部来自实证返工判例。**回流方向（母本唯一编辑点）**：项目会话中出现新教训，先按同格式写入**项目台账**（说明文档.md）；收尾时由人工/主会话誊回**本母本文件**末尾并递增编号，再单向同步到发现副本。发现路径的副本一律不改——直接改副本会在下次同步时被母本覆盖丢失。

## 采集侧

**L1 · timeout ≠ noop**
现象：笔记记录「点击无响应/零请求」，复刻按 noop 实现，审查判定行为反向。
根因：点击实际触发了 `TimeoutError`（选择器定位失败），被误读成"无响应"。
对策：任何「零请求/无响应」结论必须三证互洽——点击日志 result 字段 + 截图校验和 + 目标源码；error/timeout ≠ noop。

**L2 · 选择器口径误读**
现象：结论「翻页器不存在/为空」，复刻漏掉翻页器。
根因：枚举脚本只找 `button/a` 标签，原站翻页器是 `span` 结构。
对策：可点元素枚举后与渲染 DOM 直接 diff；「不存在」类结论需 DOM 证据+交互日志+截图三方互洽。

**L3 · 跳转壳被误判为空壳**
现象：1KB 的 HTML 被当成"待 JS 渲染的空壳页"。
根因：未读源文件全文。
对策：小文件先读全文——几行 `location.replace` 就是入口路由，按壳复刻并验证落点。

**L4 · 同名不同产品**
现象：拿旧项目的同名系统材料当事实源，实际两个产品毫无代码关系。
根因：只对了名字没验身份。
对策：登录页特征、静态资源指纹、接口前缀三处核实；GOAL 里显式写「与 XX 材料是否同一产品」的结论。

**L5 · 账号状态污染契约样例**
现象：登录失败锁定阈值被采成 3 次，实为 5 次。
根因：采集前账号已有 3 次失败计数，服务端累计状态污染了"新鲜态"样例。
对策：计数型契约用全新会话复测；参考样例失真要在文档里留勘误。

**L6 · 证据链断裂**
现象：报告称「实证通过」，归档日志却是"跳过"。
根因：断言跳过未显式登记。
对策：归档日志必须是最终态；跳过/超时的用例显式标注；抽验时核对日志与结论一致。

**L7 · 版本漂移**
现象：采集期目标系统持续发版，前后材料口径不一。
根因：未登记版本快照。
对策：GOAL 记版本号；差异走增量重抓（旧文件加日期后缀）。

**L8 · 懒加载漏采**
现象：长列表只采到首屏，接口与数据缺失。
根因：未滚动触发懒加载。
对策：滚动到底再抓 DOM+接口；长列表抓第 1、2 页。

## 建造侧

**L9 · 仅改注释 ≠ 重写**
现象：自述"结构性重写"，审查实测与原站重合 99%。
根因：只改写了注释，逻辑逐字保留。
对策：剥注释 difflib 自证 <40%；手法=函数边界重排/符号改名/实现路径替换；允许重合仅限契约串/CSS 值/文案/模板。

**L10 · 自测口径漂移**
现象：自述相似度 36.7%，审查实测 41.3%（超线）。
根因：自写剥注释口径比审查口径保守。
对策：相似度自证直接运行 `node <skill>/scripts/similarity.mjs <复刻> <原型>`，禁止自写口径。

**L11 · 重写引发契约断裂**
现象：重写时改了跨文件共享符号名，运行时 ReferenceError。
根因：改名未查跨件引用。
对策：建立跨件契约符号清单，重写后逐个核验在位；行为断言全量重放。

**L12 · unwrap 通道判型死分支**
现象：保存成功但提示失败——回调对已解包响应判 `code !== 0`（恒真）。
根因：API 封装成功时只回传 data，code 已被剥掉；同文件他处有正确写法未参照。
对策：封装通道的判型统一参照同项目正确用例；同类误用全文件 grep 排查。

**L13 · 公共件绑定机制选择**
现象：复刻"失败也关弹窗"，原站实为保持打开可改重试。
根因：公共弹窗件用了 addEventListener，原站用 onclick 属性赋值（可被页面覆盖）——机制不同构。
对策：公共件行为逐条对照原站实现机制（非仅现象）；改动公共件必须全站排查依赖并回归。

**L14 · 兜底默认值泄漏口令**
现象：目标站真实口令被写成 mock 后端的兜底默认值，随代码入库。
根因："方便启动"给了默认值。
对策：凭据缺配置一律启动报错；全产出定期扫描口令 0 命中。

**L15 · 账本/口径类细节想当然**
现象：把"积分"与"钱包"混为一谈；把价格字段当数字实为字符串。
根因：未逐字段核对抓包。
对策：契约对齐做值级/指纹比对；金额/计数类字段逐个验证类型与单位。

**L16 · 任务书与事实源冲突时跟错**
现象：任务书描述的交互与采集材料矛盾，建造按任务书实现后被审查推翻。
根因：材料是唯一事实源——任务书也会写错。
对策：建造者发现矛盾时按材料实现并登记矛盾；审查方对这类点做源码级裁定。

## 审查侧

**L17 · 审查脚本自身出错**
现象：审查断言失败，实为脚本选择器/等待/口径写错。
根因：审查工具也会错。
对策：断言失败先甄别"复刻缺陷 vs 脚本缺陷"，甄别过程留痕进报告。

**L18 · 一次过审≠审查放水**
现象：后期批次出现零 FAIL 一次过审。
根因：前期返工教训内化到建造纪律（自检主动返工后才交付）。
对策：保持抽查加严（独立抽查/第二智能体复核 20%），防止审查疲劳。

## 流程侧

**L19 · 并发多智能体 token 失控**
现象：并行派发导致配额极速消耗。
根因：无串行纪律。
对策：默认串行（一个子智能体完成验收后再派下一个）；任务书写短写聚焦。

**L20 · 中断后现场不明**
现象：限额/断网打断后，不知道做到哪了。
根因：进度台账更新不及时。
对策：每批完成/每次审查结论立即写台账；新会话只从台账断点接续。

**L21 · 一会话只能挂一个定时任务**
现象：想给已属定时任务的会话再建任务被拒。
根因：宿主限制。
对策：改建现有任务；或在新会话建新任务。

**L22 · 误触写操作**
现象：采集时点了"对账核验"类按钮，触发服务端真实同步。
根因：按钮语义不直观，未识别为写操作。
对策：拿不准的按钮先查源码绑定行为再点；误触立即登记「测试产生」并评估影响；红线黑名单按目标域扩充进采集脚本。
