# 01 · 阶段流程详解

> 每个阶段四要素：做什么 / 产出 / 验收门禁 / 常见坑（坑的完整版见 06-教训清单）。

## 阶段 0 · 环境与工具

**做什么**：运行 `scripts/preflight.mjs`；按 deps-manifest 分层装依赖（核心层自动装，按需层征确认）；确认采集通道（Web：浏览器 RPA + 抓包；桌面：桌面 RPA + 消息/抓包；Electron：CDP 直连）。

**产出**：环境自检报告（含装后版本回读）。

**门禁**：核心层全绿，或不可用项已降级登记（如无 Chrome → 已自动下载 chromium）。

**坑**：npm 源不通先配镜像；Windows 无 bash，一切脚本走 Node；公司代理环境透传 `HTTPS_PROXY`。

## 阶段 1 · 摸底与 GOAL 计划

**做什么**：
1. **鉴别目标身份**：确认目标域名/软件与任何已有材料是否同一产品——同名不同产品是高发陷阱（判例：两个"GEO"系统，一个是老式 FastAdmin 后台、一个是自研 MPA，毫无代码关系）；
2. **判定目标类型**：Web MPA / Web SPA / 桌面原生 / Electron / 移动 App → 决定采集手段与复刻栈（矩阵见 02）；
3. **最小侦察**：匿名可达性、登录方式、技术栈指纹、页面/菜单清单初稿、版本号快照；
4. **写 GOAL 计划**：目标/非目标、已确认决策（技术栈/推进方式/后端深度/特殊能力/合规红线——每项向用户确认一次）、分期分批表、质量闭环定义、验收标准、风险对策；
5. `scripts/scaffold.mjs` 创建项目骨架；目标账号写入项目 `.env`（gitignore）。

**产出**：GOAL 计划、说明文档（进度台账）、项目骨架。

**门禁**：用户批准 GOAL（含技术栈决策）后才进入采集/建造；采集可与批准并行启动。

**坑**：演示站与生产站是两个系统；版本号要记录（目标会持续迭代，后续差异走增量重抓）。

## 阶段 2 · 全量采集（唯一事实源）

**做什么**：对每个可达页面采"五件套"（标准见 02 §一）；枚举隐藏路由；按授权分级采集（L0-L3，见 07）；浏览器线与静态线并行。

**产出**：`逆向采集/` 目录（01_入口与登录 / 02_页面/N-页面名 / 03_接口 / 04_前端资源 / 05_交互状态 / 06_本地存储 / 复刻分析.md）。

**门禁**：页面清单闭环（菜单 × JS 路由交叉 = 无遗漏）；每页五件套齐备；采集陷阱防御全部执行（见 02 §四）。

**坑**：见 02 §四「采集陷阱防御」——这是返工率最高的环节。

## 阶段 3 · 静态逆向

**做什么**：静态资源全量镜像（保持原相对路径）；JS 静态分析提取接口/存储/路由清单（Web 推荐 REA CLI：`npx rea-agents analyze-javascript-application <目录> --json`，大输出落临时文件用 jq 提取后即删）；与阶段 2 抓包交叉印证——**动态抓包证明行为，静态代码证明意图**，两者合并成完整接口清单。

**产出**：接口清单（实测/静态分列）、资源清单（URL→本地路径→sha256）、复刻分析（路由总表/数据模型推断/复刻 checklist）。

**门禁**：清单双源交叉后无孤证；静态拿不到的（POST 体/图表数据）列入「待动态补采清单」移交阶段 2 补。

## 阶段 4 · 分批建造

**做什么**：按域分批（每批 ≤1 个重页或 ≤5 个轻页）；每批走「建造→自测→实现说明」；复刻栈按 03 §一决策矩阵；全部业务代码结构性重写。

**产出**：frontend/ + mockserver/（或按 03 §一选定的栈）+ 每批实现说明。

**门禁**：自测套件全绿（断言数落档）；相似度自证用审查方口径 <40%；跨页联调项登记。

## 阶段 5 · 质量闭环（每批必过）

**做什么**：独立审查子智能体（未参与建造）按审查任务书逐项复验 → FAIL 清单（根因分类：真缺陷/采集时点差异/站方Bug/批次边界）→ 建造返工 → **定向复验**（只验 FAIL+波及面）→ 通过收官。

**产出**：每批一份审查报告（一批一档）+ 建造实现说明（一一对应）。

**门禁**：审查通过；FAIL 不存在未处置项（修复或折入后续批次并显式登记）。

## 阶段 6 · 终验归档

**做什么**：全站逐按钮总盘点（自动化枚举全部可点元素 → 逐条对照批次证据 → 未覆盖的实测）；全站回归（20+N 路由扫描 + 各批自测套件重放）；写总验收报告（结构/使用方式/质量数据/遗留统一口径/可选深化）；归档清单。

**产出**：inventory 报告（每元素带结论与引用）、总验收报告。

**门禁**：质量指标速查表全部达标；遗留统一口径完整（每条：现象/影响/处置建议/是否需用户裁定）。

## 断点续跑协议（长项目必读）

1. **进度台账**：项目根 `说明文档.md` 的进度表是唯一断点事实源——每批完成、每次审查结论、每个遗留、每次用户裁定，立即写入；写法=「日期 | 事实+数据」，不写过程性废话。
2. **会话接续**：新会话第一步=读台账最后几行 → 判断断点 → 只推进一个原子步骤。
3. **中断应对**：限额 → 停在批次边界，台账记断点；断网 → 子智能体断点续跑（带上下文 SendMessage 续），已产出的证据不重做；换电脑 → 项目目录整体拷走（skill 只提供流程与脚本）。
4. **长周期**：可配定时任务在额度恢复时段自动激活接续（一次性任务，读台账断点执行）。

## 授权分级（L0-L3）

| 级别 | 允许动作 | 留证要求 | 授权要求 |
| --- | --- | --- | --- |
| L0 | 只读浏览、截图、DOM、抓 GET | 常规 | 目标归属方同意即可 |
| L1 | 交互点穿：弹窗/抽屉/tab/下拉全开 | 每状态截图+DOM 子树 | 同上 |
| L2 | 写操作契约：到确认态取消；或授权后实测 | 确认态截图 + 推断契约登记 | **显式授权**；实测后删除测试数据 |
| L3 | 计费/消耗/外发类真实触发 | 全程留证 + 金额影响报告 | **显式授权 + 限额确认** |

默认工作在 L0-L1；L2 按「推断契约实现 + 演示开关」替代；L3 未授权则登记为盲区（不阻塞复刻）。
